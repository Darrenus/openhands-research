# 跨模块设计原则索引

> 这份文档不是对某一个模块的拆解，而是把 `notes/02` 到 `notes/23` 这 22 篇精读里
> **反复出现的设计原则**归并到一处。
>
> 归并的标准是：**同一条原则在至少两个互不相干的模块里各自出现过。**
> 出现次数越多，说明它越可能是这个团队的共识，而不是某一处的巧合。
>
> 每条原则下面列出它的出现位置。**建议的读法**：先看这份索引建立骨架，
> 再去读具体那一节看它在真实约束下长什么样。

## 1. "未知"必须是独立的、可检测的状态（8 次）

**这是整个项目出现次数最多的一条原则。**

核心是：**"我不知道"和"没问题"是两件完全不同的事，在数据上必须能区分开。**
如果用同一个值表示，那么"从未成功判断过"会伪装成"一切正常"——
**监控是绿的，功能是死的，而且极难发现。**

| 出现位置 | 形态 |
|---|---|
| `07-security` | `SecurityRisk.UNKNOWN` **不参与大小比较**，比较它直接抛异常 |
| `07-security` | shell 语法分析三档输出：是 / 否 / **`uncertain`** |
| `11-tool-layer` | `declared=False`（我没想过）vs `declared=True, keys=()`（我想过了，安全） |
| `14-hooks` | `_fall_open` 返回 `success=False` + `decision=ALLOW`，于是"没能判断的放行"可检测 |
| `15-routing` | 分类器给不出有效答案就**报错**，拒绝静默路由到默认模型 |
| `17-acp-agent` | 拿不到用量数据就说"追踪不可用"，**不记 0** |
| `21-task-manager` | 非 `FINISHED` 的终止一律算错误，**不算"完成但结果为空"** |
| `23-agent-server` | `state_signature = None` 表示"还没验证过，必须重读" |

**最能说明危害的一句注释**（`14-hooks`）：
一个无法识别的决定值必须是可检测的降级，**而不是一个伪装成真实决定的静默放行**
（`masquerades as a real decision`）。

## 2. 不可变 + 只增 + 只读投影（4 次）

**危险操作永远碰不坏真实记录。**

| 出现位置 | 形态 |
|---|---|
| `02-event-model` | 事件 `frozen=True`，`events_to_messages` 是只读投影 |
| `03-view-and-properties` | 压缩不是删除，而是**追加一条"这里开始用摘要代替"的记录** |
| `06-condenser` | 压缩记录记"忘了哪些 id"而不是"留了哪些"（下标会漂移，id 不会） |
| `21-task-manager` | 会话对象可以被销毁，因为全部状态在账本里，按 id 就能恢复 |

## 3. 原始数据和加工数据分开存（4 次）

**忠实度和安全性/可读性不必二选一。**

| 出现位置 | 形态 |
|---|---|
| `02-event-model` | `tool_call`（模型原始输出，含自评风险）vs `action`（校验后的执行参数） |
| `11-tool-layer` | `content` 是事实，`to_llm_content` 是为特定用途做的投影（出错时才加标记） |
| `13-tool-implementations` | 文件编辑器同时存改动前后内容，展示时生成 diff |
| `19-secrets-and-git` | 脱敏用 `model_copy` 生成新对象，不改原始事件 |

<a id="4"></a>
## 4. 存档的寿命比代码长（5 次）

**你的持久化数据会活过依赖库的大版本、活过参数的废弃、活过滚动升级。**

| 出现位置 | 形态 |
|---|---|
| `02-event-model` | `extra="forbid"` + `kind` 字段：schema 漂移立刻炸，而不是静默丢字段 |
| `11-tool-layer` | MCP 落盘用**协议规定的字段名**，不用当前依赖库恰好用的名字 |
| `21-task-manager` | 废弃参数分两步：先 `SkipJsonSchema` 从 schema 隐藏，再等大版本删字段 |
| `23-agent-server` | 租约的新字段是可选的，老文件没有就退化成旧行为（滚动升级期间新旧并存） |
| `23-agent-server` | `include_in_schema=False`：从 API 文档隐藏但继续接受 |

<a id="5"></a>
## 5. 互斥的字段要一起设置（2 次）

| 出现位置 | 形态 |
|---|---|
| `21-task-manager` | `set_result` 清掉 error，`set_error` 清掉 result |
| `08-critic` | 成功/失败的判定集中在一处，不让调用方分两步赋值 |

**状态机的转移应该是原子的**——分两步赋值中间会有一个不一致的瞬间，而且容易忘掉清另一个。

<a id="6"></a>
## 6. 错误信息要包含"下一步怎么办"（9 次）

**第二高频的原则。** 给模型（或用户）的错误信息，
要包含**足够让它自己改对的一切**，而不只是"失败了"。

| 出现位置 | 形态 |
|---|---|
| `04-agent-step` | 工具不存在时附上**完整的可用工具列表** |
| `08-critic` | 反馈带具体的问题标签和概率（"测试不足 85%"） |
| `09-context-engineering` | 技能描述被截断时附上 `invoke_skill(name="x")` 的调用写法 |
| `13-tool-implementations` | Python 字面量检测器给出**两种正确做法的完整示例** |
| `13-tool-implementations` | 多次匹配时列出所有行号；白名单拒绝时列出允许的文件 |
| `15-routing` | 分类失败时带上分类器**原始回复** + 两条不同的修复建议 |
| `18-browser-and-patch` | 找不到 Chromium 时报错信息是**安装指引** |
| `21-task-manager` | 任务找不到时列出所有可用任务 |
| `22-subagent-*` | Oracle 没配置时告诉你"存一个叫 oracle 的配置就能启用" |

**反面**（`22-subagent-*` 里点名的）：
`except Exception: return "Oracle failed"` ——AI 完全不知道是配置问题、
网络问题还是模型问题，**也就没法决定要不要重试。**

<a id="7"></a>
## 7. 不要用泛化错误覆盖精确诊断（4 次）

| 出现位置 | 形态 |
|---|---|
| `05-run-loop` | 兜底前先查 `_agent_already_surfaced_error`，避免 `str(e)` 盖掉结构化错误（注释用词 `clobber`） |
| `06-condenser` | `raise B from A` 保留异常链，否则只看到"补救失败"看不到"最初为什么需要补救" |
| `12-workspace-and-server` | 完成回调优先用 `ConversationRunError` 里的结构化错误事件 |
| `21-task-manager` | 停止原因优先用最后一条 `ConversationErrorEvent` 的详情 |

**很多项目日志难读，就是因为每一层都往上包一层没信息量的错误。**

<a id="8"></a>
## 8. fail-closed 还是 fail-open，取决于"谁的代码出了问题"（6 次）

**这一条最有意思的地方是：同一个项目里两种相反的取向并存，而且各有明确理由。**

| 出现位置 | 取向 | 理由 |
|---|---|---|
| `07-security` | **closed**：检查器抛异常算 HIGH | 是 SDK 自己的代码，出 bug 必须保守 |
| `16-skills-loading` | **closed**：路径解析异常算"在仓库外" | 符号链接逃逸的后果是泄露私钥 |
| `23-agent-server` | **closed**：不确定进程是否存活就当活着 | 抢错租约 = 两个进程同时写 |
| `14-hooks` | **open**：退出码 1 不拦截 | 钩子是**用户写的任意脚本**，它的拼写错误不该让 agent 瘫掉 |
| `08-critic` | **open**：评审员挂了就跳过 | 少一次优化机会，不该让整个任务失败 |
| `18-browser-and-patch` | **open**：录制失败不阻塞浏览器操作 | 录制是次要功能 |

**判断依据**：问两个问题——**这是谁的代码出了问题？失败的代价是什么？**

<a id="9"></a>
## 9. 重试只在结果可能不同的时候才有意义（3 次）

**确定性失败必须先改变某个条件，否则重试 5 次只是把同一个失败做 5 遍。**

| 出现位置 | 形态 |
|---|---|
| `10-llm-seam` | 空响应且 temperature=0 时，**先把温度改成 1.0 再重试** |
| `06-condenser` | "内容策略拦截是确定性的"，所以要注入"换个说法"而不是原样重试 |
| `11-tool-layer` | `idempotentHint` 标注的语义就是"重复调用是否有额外效果" |

<a id="10"></a>
## 10. 只对"对方的问题"降级（2 次）

| 出现位置 | 形态 |
|---|---|
| `10-llm-seam` | 换备用模型的异常清单**全是对方的问题**（连不上、限流、超时、500） |
| `15-routing` | 分类失败**不**降级——那是自己的配置问题，换个默认模型只会掩盖它 |

参数写错了、内容被过滤了换个模型也一样失败，**换只是浪费钱。**

<a id="11"></a>
## 11. 把报错变成对话，而不是崩溃（5 次）

**这是 agent 架构特有的一条**：很多失败可以写成一条消息交给模型，让它自己修。
而且这个手法在五个地方用了同一种实现（往事件流里加一条消息），**不需要特殊控制流**。

| 出现位置 | 形态 |
|---|---|
| `04-agent-step` | 函数调用格式错误 → 把错误信息**伪装成一条用户消息**塞回去 |
| `04-agent-step` | 被内容过滤拦了 → 注入"你被过滤了，换个说法继续" |
| `05-run-loop` | 卡死检测 → 注入一句带事实、否定和出路的提醒 |
| `05-run-loop` | 停止钩子否决结束 → 把钩子的反馈作为消息注入 |
| `08-critic` | 评审不过线 → 注入带具体标签的追加要求 |

**一个项目里反复出现同一个手法，说明它是真的想清楚了的架构选择，而不是巧合。**

<a id="12"></a>
## 12. 失败的结果里要带上已完成的部分（2 次）

| 出现位置 | 形态 |
|---|---|
| `21-task-manager` | 子 agent 超步数时，错误详情里拼上部分输出（而且**只在真有输出时才拼**） |
| `06-condenser` | 硬性上下文重置失败时，两个异常都保留在链上 |

**"失败"和"什么都没有"是两件事**——一个跑了 90% 才失败的任务，那 90% 可能仍然有用。

<a id="13"></a>
## 13. 脱敏/校验要放在数据流的收窄处（7 次）

**核心思路：不要依赖每个人都记得做正确的事，要让正确的事成为唯一的通路。**

| 出现位置 | 收窄处在哪 |
|---|---|
| `11-tool-layer` | 所有工具输出经过同一个 `__call__` **出口**，在那里脱敏一次 |
| `04-agent-step` | 错误信息只放参数名不放值（因为值会流向日志和遥测） |
| `12-workspace-and-server` | FastAPI 的 422 校验响应会回显请求体，**拦下来脱敏**（挂着真实 issue） |
| `13-tool-implementations` | 给第三方库 libtmux 的日志器装过滤器（**最容易被忘掉的通道**） |
| `17-acp-agent` | 因为有**多个出口**（正常发出 / 取消时补发），所以放在**入口**做 |
| `18-browser-and-patch` | 截图字段用 `SkipSecretMasking()` 做**显式、可审计的例外** |
| `19-secrets-and-git` | 三层防护（知道确切值 / 知道键名 / 只有纯文本）+ 流式跨块脱敏 |

**判断这个位置该放入口还是出口**：数一数有几个入口几个出口，放在少的那一侧。

**判断脱敏能有多可靠**：看你有多少上下文——
知道确切值 → 精确替换；知道键名 → 按名字猜；只有纯文本 → 按字面量前缀猜。

## 14. 默认值要选"忘了配置也不会出事"的那个（5 次）

| 出现位置 | 形态 |
|---|---|
| `11-tool-layer` | `ToolAnnotations` 四个维度默认全倒向危险（会改环境、有破坏性、不幂等、碰外部） |
| `07-security` | `confirm_unknown=True`：检测器说"不确定"时默认要确认 |

| `22-subagent-*` | `permission_mode` 省略即继承父策略，不取系统默认 |

**不是选"最常用"的那个，是选"配错了也不会出事"的那个。**

<a id="15"></a>
## 15. 被迫的安全妥协要多处留痕（4 次）

| 出现位置 | 形态 |
|---|---|
| `18-browser-and-patch` | root 下必须关 Chromium 沙箱：`SECURITY:` 注释 + 运行时 warning + 限定使用场景 |
| `20-observability-*` | **写出 AST 校验的已知绕过方法**，并论证为什么不构成安全问题 |
| `17-acp-agent` | 脱敏失败时放原值，注释明确承认"**可能瞬时泄露凭证**但避免崩溃" |
| `17-acp-agent` | 为隔离 Gemini 只能改 `HOME`，写清副作用（git/npm 也看到新家目录）并给退出选项 |

**一个被记录的已知缺陷，比一个没人知道的正确假设更安全。**
而且**只写注释不够**——跑起来的人看不到代码，所以要有运行时日志。

<a id="18"></a>
## 18. 判断一个值是不是秘密，看"拿到它能做什么"（3 次）

| 出现位置 | 形态 |
|---|---|
| `17-acp-agent` | ACP 会话 ID **持有即可恢复会话**，所以默认序列化打码 |
| `19-secrets-and-git` | `KEY` 这个模式会误报 `primary_key`，**这是有意的**——宁可多打码 |
| `23-agent-server` | WebSocket 令牌不放 URL，因为 **URL 会进反向代理的访问日志** |

**已知的泄露渠道清单**（散在三节里）：日志、追踪导出、**PR 评审附件**、
URL（被中间设施记录）、第三方库的日志、API 校验错误的回显。

<a id="19"></a>
## 19. 顺序不是随意的：前缀缓存与顺序截断（3 次）

**两个看起来相反、其实同源的例子：**

| 出现位置 | 方向 | 机制 |
|---|---|---|
| `09-context-engineering` | 变化最频繁的放**最后** | **前缀缓存**：开头一个字变了后面全部重算 |
| `11-tool-layer` | 重要的短字段放**最前** | **顺序生成 + 长度上限**：截断会切掉后面的必填字段 |
| `22-subagent-*` | 遍历必须 `sorted()` | **"先来先得"的规则需要确定的顺序**，否则不同机器上胜者不同 |

**先问：这个系统是从前往后读（缓存），还是从前往后写（截断）？**

## 43. 预算/统计的完整性取决于一条纪律（6 次）

**这条链路横跨六个模块，缺一环整个预算控制就失效——而且不会报错。**

| 出现位置 | 这一环做什么 |
|---|---|
| `06-condenser` | 摘要模型用 `model_copy` 派生，**仍共享用量统计** |
| `05-run-loop` | `get_combined_metrics()` 把**所有模型**的花费加总（主模型+压缩+评审） |
| `15-routing` | **"调用一个未注册的 LLM 会产生账外开销"**——必须先注册进登记表 |
| `14-hooks` | 钩子用量按 `usage_id` 单独记账再合并（而且防止对象和自己合并） |
| `21-task-manager` | 子 agent 的统计是**累计值**，所以要**替换**而不是合并（合并会翻倍） |
| `12-workspace-and-server` | 会话结束时 `register_cost` 上报到工作区，默认就有不需 opt-in |

**一个功能（成本可见）需要六个模块配合，而任何一个绕过登记的调用点都能让它失效。**
所以 `15-routing` 那段注释专门写清了"为什么必须注册"。

## 尾声：几条只出现一次但值得单独记的

这些没进上面的归并（只出现过一次），但单独看很有价值：

- **`14-hooks`**：**把"故意拒绝"分配给一个不会被意外触发的值。**
  退出码 1 是 Unix 世界"出错了"的默认值，所以拦截用 2——
  否则钩子脚本的一个拼写错误会让 agent 完全瘫掉。

- **`23-agent-server`**：**光有过期时间的租约不安全，必须有单调递增的代数（围栏令牌）。**
  一个暂停后恢复的旧持有者能靠代数发现自己已被取代。

- **`19-secrets-and-git`**：**流式脱敏扣住"最长可能模式长度 - 1"的尾巴。**
  这个数保证任何跨块匹配都还完整地留在缓冲区。

- **`19-secrets-and-git`**：**同一个计算给不同消费者用时，可能需要不同的参数。**
  导出用的 diff 基准必须"在别处能重建"，展示用的要"让人看清干了什么"。

- **`16-skills-loading`**：**缓存策略由"数据能不能变"决定，而不是统一给一个 TTL。**
  分支引用 60 秒过期，标签和提交 SHA 用 `float("inf")` 永不过期。

- **`16-skills-loading`**：**让文件系统的位置决定规则的作用范围。**
  子目录里的 `AGENTS.md` 自动变成只在该目录生效的路径规则——
  用户不需要学配置语法。

- **`23-agent-server`**：**让"时间"成为可注入的依赖。**
  把 `sleep` 做成一个字段，含退避/超时的代码的测试成本降一个数量级。

- **`17-acp-agent`**：**超时要先问"这个过程有没有可观测的中间进度"。**
  有 → 空闲超时（持续干活就不中断）；没有 → 硬超时。

- **`21-task-manager`**：**重复代码往往标记出一个还没被抽象出来的概念。**
  三处子 agent 实现里那段"跑到完成并处理审批"的循环逐字重复。

- **`23-agent-server`**：**把库变成服务时，新增的复杂度应该集中在"多"上。**
  如果业务逻辑在服务层重新实现了一遍，说明库的抽象有问题。
